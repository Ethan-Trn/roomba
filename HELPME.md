# HELPME: how to build and run room

## Run it (do this every time)

```bash
cd ~/Downloads/roomba                  # workspace root (the folder containing src/)
source /opt/ros/lyrical/setup.bash     # teach this terminal about ROS
colcon build --packages-select roomba  # copy src/ into install/ (redo after code changes)
source install/setup.bash              # teach this terminal about my package like all laptop and pi stuff
```

Then, in two terminals (each needs both `source` lines):

```bash
ros2 run roomba laptop    # terminal 1: publisher (topic.py)
ros2 run roomba pi        # terminal 2: subscriber (sub.py)
```

Terminal 2 should print `i see message 0`, `1`, `2`, ...

## What each thing is

| Thing | Meaning |
|---|---|
| `src/` | my code. The only folder I edit |
| `colcon build` | copies src/ into install/ in the layout ROS expects |
| `build/`, `install/`, `log/` | generated by colcon. Safe to delete, never edit |
| `source ...setup.bash` | tells THIS terminal where ROS / my package live. Redo in every new terminal |
| `setup.py` `entry_points` | makes the commands `laptop` and `pi` (format: `name = package.file:function`) |
| `data_files` in setup.py | copies non-Python files (package.xml, launch files, configs) into install/ |
| node | a running program in ROS (`talker`, `listener`) |
| publisher / subscriber | parts inside a node that send / receive messages on a topic (`mf`) |

## Names that are different things

```
ros2 run roomba laptop
          │       └─ command name   (setup.py entry_points)
          └─ package name

main() -> Talker() -> super().__init__('talker')
                                        └─ node name in ROS (ros2 node list)
```

## Common errors

- `ros2: command not found` -> forgot `source /opt/ros/lyrical/setup.bash`
- `package 'roomba' not found` -> forgot `source install/setup.bash`, or never ran `colcon build`
- code change not showing up -> rebuild with `colcon build` (or use `colcon build --symlink-install` once so Python edits apply without rebuilding)
- `colcon build` says no packages -> you're not in the workspace root

## The lidar code (what each file does)

| File | What it does |
|---|---|
| `ld06.py` | turns the lidar's raw bytes into distances and angles: finds each packet, checks it wasn't corrupted, reads the measurements, gathers a full circle. Knows nothing about ROS or wires |
| `sources.py` | provides the bytes. UART version reads the Pi's pins, USB version reads the USB adapter, simulated version makes up a room so you can test without the sensor |
| `lidar_node.py` | the program you run on the Pi. Takes bytes from `sources.py`, passes them through `ld06.py`, publishes each finished circle as `/scan` |
| `test/test_ld06.py` | checks `ld06.py` works without needing the sensor |
| `setup.py`, `package.xml` | tell ROS the `lidar` command exists and what it needs installed |
| `CLAUDE.md` | notes on project layout and Pi setup |

```
sources.py -> ld06.py -> lidar_node.py -> laptop (RViz)
(get bytes)   (decode)   (send to ROS)    (draw it)
```

## Run the lidar

```bash
ros2 run roomba lidar --ros-args -p source:=sim     # fake room, no sensor needed
ros2 run roomba lidar --ros-args -p source:=uart    # real sensor on the Pi's GPIO pins
ros2 run roomba lidar --ros-args -p source:=usb     # real sensor on the USB adapter
```

The node logs `scans/s` and `bad_crc` every 5 seconds. `scans/s` should be near 10 and
`bad_crc` near 0. That log line is only for debugging, it does not change what gets published.

Run the tests (no ROS or sensor needed, run from `src/roomba`): `python3 -m pytest test/test_ld06.py`

## See it in RViz (laptop)

Terminal 1, start the node (use `sim` until the sensor is wired):

```bash
cd ~/Downloads/roomba
source /opt/ros/lyrical/setup.bash
source install/setup.bash
ros2 run roomba lidar --ros-args -p source:=sim
```

Terminal 2, open RViz on the same domain as the node (67):

```bash
source /opt/ros/lyrical/setup.bash
ROS_DOMAIN_ID=67 rviz2
```

In the RViz window:

1. Global Options -> **Fixed Frame** = `lidar` (must match the node's `body_frame` parameter)
2. **Add** -> By display type -> **LaserScan**
3. LaserScan -> **Topic** = `/scan`
4. Size (m) about `0.03`, Style = `Points` or `Spheres`. If nothing shows, set Reliability Policy to `Reliable`

You should see a ring of dots shaped like a rectangle room with a small pillar (the sim).

If nothing shows: Fixed Frame is not `lidar`, RViz was started without `ROS_DOMAIN_ID=67`, or the node is not running.

## How the lidar data flows

```
lidar --packets--> Pi (parser, assembler) --LaserScan--> laptop (RViz)
      47 bytes                             ~450 distances
      12 points                            one full circle
      ~375 per second                      ~10 per second
```

- A **packet** is the lidar's own format: 12 points, a start angle, an end angle and a CRC. Only exists between lidar and Pi.
- The 12 point angles are spaced evenly between start and end angle. Each packet covers ~9.6 degrees.
- **CRC** is a check number at the end of every packet. If it does not match, the packet is corrupted and dropped.
- The **assembler** collects points until the angle wraps past 360, then returns one full turn. It returns `None` while the turn is still in progress.
- Every point of the turn is published in `ranges` (no bins). RViz works out each angle as `angle_min + i * angle_increment`. A point with no echo is `inf` so the spacing stays even.
- Sensor angles go clockwise, ROS wants counter-clockwise, so the code flips them (`360 - angle`).

## Functions in `lidar_node.py`

| Function | What it does |
|---|---|
| `_alert` | timer callback, runs every 5 ms. Reads bytes, finds packets, adds them to the turn, publishes when a turn is done |
| `_publish` | fills in a `LaserScan` message and sends it on `/scan` |
| `_update` | prints the status line every 5 seconds (debugging only) |
